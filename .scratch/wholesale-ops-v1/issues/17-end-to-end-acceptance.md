# 17 — 完整旅程验收与界面收口

**What to build:** 把各业务切片收敛为一条稳定可演示的完整旅程，验证真实权限、数据库联动、异常场景、响应式界面、日志安全和生产构建达到首版验收线。

**Blocked by:** 06 — 客户 Excel 导入；10 — 取消销售单并释放预占；13 — 撤销收款；14 — 经营总览；15 — 按权限和筛选条件导出；16 — 确定性演示数据与备份恢复

**Status:** ready-for-agent

- [ ] Playwright 从真实登录开始验证销售创建含两个 SKU 的草稿、确认预占、仓库整单出库、财务部分收款与撤销、老板查看经营总览和业务审计。
- [ ] 浏览器旅程验证销售、仓库和财务的导航、字段和服务端数据范围，尤其确保仓库永远看不到成交价与应收。
- [ ] 浏览器旅程覆盖库存不足整单拦截、含错误行 Excel 的整批阻止、当前筛选结果导出以及演示数据重置。
- [ ] 领域单元测试覆盖状态转换、金额、账期、到期日、结算状态、权限决策和数据范围。
- [ ] 真实 PostgreSQL 集成测试覆盖 migration、唯一约束、事务回滚、并发预占、取消与出库竞争、收款及业务审计原子性。
- [ ] 正式应用在 1440px 下保持已批准原型的账本网格视觉、信息密度、状态层级和关键交互，不回退为默认组件库外观。
- [ ] 390px 下导航、列表、详情、对话框和收款抽屉没有水平溢出，常用查询及基础操作不被布局阻断。
- [ ] 主验收浏览器为最新版 Chrome/Chromium；不新增正式 WCAG 或跨浏览器自动化矩阵范围。
- [ ] 日志安全测试证明密码、授权头、Cookie、会话、原始 Excel 行和客户敏感字段不会进入结构化输出。
- [ ] 代码检查、类型检查、全部自动化测试、生产构建和连续三次演示重置全部通过，且没有遗留阻断演示的控制台错误。
