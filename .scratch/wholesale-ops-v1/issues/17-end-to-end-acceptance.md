# 17 — 完整旅程验收与界面收口

**What to build:** 把各业务切片收敛为一条稳定可演示的完整旅程，验证真实权限、数据库联动、异常场景、响应式界面、日志安全和生产构建达到首版验收线。

**Blocked by:** 06 — 客户 Excel 导入；10 — 取消销售单并释放预占；13 — 撤销收款；14 — 经营总览；15 — 按权限和筛选条件导出；16 — 确定性演示数据与备份恢复

**Status:** resolved

- [x] Playwright 从真实登录开始验证销售创建含两个 SKU 的草稿、确认预占、仓库整单出库、财务部分收款与撤销、老板查看经营总览和业务审计。
- [x] 浏览器旅程验证销售、仓库和财务的导航、字段和服务端数据范围，尤其确保仓库永远看不到成交价与应收。
- [x] 浏览器旅程覆盖库存不足整单拦截、含错误行 Excel 的整批阻止、当前筛选结果导出以及演示数据重置。
- [x] 领域单元测试覆盖状态转换、金额、账期、到期日、结算状态、权限决策和数据范围。
- [x] 真实 PostgreSQL 集成测试覆盖 migration、唯一约束、事务回滚、并发预占、取消与出库竞争、收款及业务审计原子性。
- [x] 正式应用在 1440px 下保持已批准原型的账本网格视觉、信息密度、状态层级和关键交互，不回退为默认组件库外观。
- [x] 390px 下导航、列表、详情、对话框和收款抽屉没有水平溢出，常用查询及基础操作不被布局阻断。
- [x] 主验收浏览器为最新版 Chrome/Chromium；不新增正式 WCAG 或跨浏览器自动化矩阵范围。
- [x] 日志安全测试证明密码、授权头、Cookie、会话、原始 Excel 行和客户敏感字段不会进入结构化输出。
- [x] 代码检查、类型检查、全部自动化测试、生产构建和连续三次演示重置全部通过，且没有遗留阻断演示的控制台错误。

## Answer

- 新增从真实登录开始的四角色 Chromium 验收旅程：销售创建并确认两行 SKU 销售单、仓库在无价格/应收信息的工作台完成整单出库、财务登记部分收款并撤销、老板核对经营总览和四类业务审计；业务结果全部通过页面与稳定用户契约断言。
- 验收旅程同时检查 1440px 正式账本网格与 390px 销售详情、确认对话框、应收详情、收款抽屉、撤销对话框和经营总览无页面级横向溢出，并收集浏览器控制台和页面错误。
- 新增纯 TypeScript 销售单与应收领域策略，覆盖状态转换、整数分金额、账期快照、中国自然日到期日、零金额/待收/部分收款/结清状态、角色权限与负责人数据范围；应用服务已复用这些规则。
- 日志输出会递归移除认证、会话、令牌、原始 Excel 行、客户敏感字段及可能承载秘密的自由文本/错误堆栈，并由安全回归测试证明敏感值不会进入结构化输出。
- Testcontainers 统一通过读取仓库固定 pnpm 版本的共享命令接缝调用 `db:migrate`、`demo:reset`、`db:backup` 和 `db:restore`，既保留公开命令契约，也消除各测试文件的重复启动实现。
- `pnpm test:acceptance` 会构建 Next.js standalone 生产包、复制静态资源、重置本机演示库并运行完整 Chromium 套件；验收模式仅可在 localhost 启用，正常生产配置继续保留 Better Auth 登录限流。
- 最终通过 ESLint、TypeScript、21 个 Vitest 文件共 185 项测试、45 项生产态 Playwright 测试、33 个路由的 Next.js production build，以及连续三次确定性演示重置；Standards / Spec 双轴复审 remaining findings 均为 0。
