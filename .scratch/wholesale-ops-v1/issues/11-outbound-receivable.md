# 11 — 整单出库并生成应收

**What to build:** 让仓库从待出库工作台完成一次完整交付，原子扣减现存量和预占量、记录库存活动并生成一笔经营应收，同时严格隐藏价格与应收信息。

**Blocked by:** 09 — 确认销售单并预占库存

**Status:** resolved

- [x] 老板和仓库可以查看全部已确认待出库销售单；销售和财务没有待出库工作台访问权限。
- [x] 仓库只看到履约所需的销售单编号、SKU、数量、库存单位，以及客户名称、联系人、电话和地址快照。
- [x] 仓库页面和服务端响应不包含成交价、销售单成交金额、应收或收款信息。
- [x] 出库确认清楚说明将交付的全部 SKU 与数量；首版没有部分数量、欠货或分批出库入口。
- [x] 服务端出库时重新验证销售单为已确认、所有预占完整存在且操作者有权执行。
- [x] 出库成功后销售单变为已出库，对应现存量和预占量同时减少，库存活动记录可追溯到销售单。
- [x] 系统按销售单全部成交金额生成且只生成一笔应收，到期日按出库日加销售单账期快照计算。
- [x] 销售单状态、数量变化、库存活动、应收和业务审计在同一数据库事务中完成，任一失败则全部回滚。
- [x] 重复出库、已取消销售单出库以及取消与出库并发竞争均只能产生一个合法终态。
- [x] 自动化测试覆盖仓库隐私边界、现结和有账期到期日、数量变化、单一应收、重复提交、事务回滚和状态竞争。

## Answer

- 已实现老板/仓库共用的待出库工作台与整单确认对话框；服务端查询 DTO 仅返回履约字段，销售和财务在页面与写入口均被拒绝，仓库侧不返回成交价、成交金额、应收明细或收款字段。
- 出库服务在 PostgreSQL `Serializable` 事务中锁定销售单和库存余额，重新校验权限、已确认状态、逐单逐 SKU 预占及现存量；成功时原子写入已出库状态、现存量与预占量扣减、`OUTBOUND` 库存活动、唯一应收和业务审计，序列化冲突有限重试。
- 应收保存客户与负责人快照、销售单全部成交金额和账期快照；数据库以销售单唯一约束保证仅一笔应收，到期日按上海时区的出库自然日加账期天数计算。销售单详情同步展示出库状态、逐 SKU 库存影响和审计轨迹。
- 自动化覆盖隐私边界、权限复核、现结/账期到期日、数量变化、单一应收、重复与非法状态、审计失败回滚，以及取消/出库并发竞争；全量 ESLint、TypeScript、135 项 Vitest、41 项 Playwright 和 Next.js production build 均通过。
- 正式页面已在 Chromium 的 1440 × 1024 与 390 × 844 视口完成真实流程 QA，确认对话框焦点管理正常，移动端无页面级横向溢出。
