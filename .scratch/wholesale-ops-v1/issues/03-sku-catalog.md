# 03 — SKU 资料管理

**What to build:** 让老板维护可供销售和库存流程使用的 SKU 资料，让销售能够查找启用 SKU，同时保证 SKU 编码稳定、历史资料可追溯。

**Blocked by:** 02 — 固定角色账号与首条业务审计

**Status:** resolved

- [x] 老板可以创建 SKU，填写唯一 SKU 编码、名称、分类、库存单位、参考售价、预警值和启用状态。
- [x] SKU 编码重复时创建失败并给出明确提示；SKU 名称允许重复。
- [x] 库存数量只支持整数口径，参考售价采用人民币定点金额并最多精确到分。
- [x] 老板可以编辑 SKU 的可变资料，但创建后的 SKU 编码只读且不能通过服务端绕过。
- [x] 老板可以停用 SKU；被业务记录引用后不能删除，尚未引用记录的删除规则与项目方案一致且有清楚反馈。
- [x] 老板和销售可以按 SKU 编码、名称、分类和启用状态筛选列表；销售只能选择启用 SKU 用于后续业务。
- [x] SKU 列表和详情预留并正确展示现存量、预占量和可用量，在尚无库存活动时均为零。
- [x] 财务和仓库只能通过其获准的业务页面获得必要 SKU 信息，不能调用老板维护能力。
- [x] 创建、编辑、停用和删除动作写入业务审计，并与资料变更保持事务原子性。
- [x] 自动化测试覆盖唯一编码、金额与整数校验、不可变编码、角色权限、停用和审计结果。

## Answer

已完成 SKU 资料的创建、组合筛选、详情与编辑、停用及未引用删除；SKU 编码由数据库唯一约束和服务端不可变规则共同保护，参考售价以整数分保存，库存数量保持整数口径。老板拥有完整维护能力，销售只读取启用 SKU，仓库和财务不能直接访问 SKU 目录或维护入口。四类资料动作均与业务审计处于同一事务，已有业务引用时删除会稳定提示改为停用。正式页面覆盖桌面宽表、移动卡片、空态、校验反馈、库存三数和只读销售详情；Vitest/Testcontainers 与 Playwright 覆盖工单列出的风险与角色边界。
