# 03 — SKU 资料管理

**What to build:** 让老板维护可供销售和库存流程使用的 SKU 资料，让销售能够查找启用 SKU，同时保证 SKU 编码稳定、历史资料可追溯。

**Blocked by:** 02 — 固定角色账号与首条业务审计

**Status:** ready-for-agent

- [ ] 老板可以创建 SKU，填写唯一 SKU 编码、名称、分类、库存单位、参考售价、预警值和启用状态。
- [ ] SKU 编码重复时创建失败并给出明确提示；SKU 名称允许重复。
- [ ] 库存数量只支持整数口径，参考售价采用人民币定点金额并最多精确到分。
- [ ] 老板可以编辑 SKU 的可变资料，但创建后的 SKU 编码只读且不能通过服务端绕过。
- [ ] 老板可以停用 SKU；被业务记录引用后不能删除，尚未引用记录的删除规则与项目方案一致且有清楚反馈。
- [ ] 老板和销售可以按 SKU 编码、名称、分类和启用状态筛选列表；销售只能选择启用 SKU 用于后续业务。
- [ ] SKU 列表和详情预留并正确展示现存量、预占量和可用量，在尚无库存活动时均为零。
- [ ] 财务和仓库只能通过其获准的业务页面获得必要 SKU 信息，不能调用老板维护能力。
- [ ] 创建、编辑、停用和删除动作写入业务审计，并与资料变更保持事务原子性。
- [ ] 自动化测试覆盖唯一编码、金额与整数校验、不可变编码、角色权限、停用和审计结果。
