# 10 — 取消销售单并释放预占

**What to build:** 让销售或老板在出库前填写原因取消已确认销售单，原子释放全部预占并永久保留销售单和取消轨迹。

**Blocked by:** 09 — 确认销售单并预占库存

**Status:** resolved

- [x] 销售可以取消自己负责客户的已确认销售单，老板可以取消任意已确认销售单。
- [x] 取消对话框说明将释放的 SKU 和预占数量，并要求填写非空取消原因。
- [x] 取消成功后销售单状态变为已取消，现存量不变、预占量减少、可用量相应恢复。
- [x] 状态变化、预占释放、库存活动记录和业务审计在同一数据库事务中完成。
- [x] 已取消销售单永久保留且不能重新启用、编辑、删除或再次取消。
- [x] 草稿和已出库销售单不能通过取消入口处理；无权销售不能取消其他负责人客户的销售单。
- [x] 并发取消或取消与出库竞争时只有一个合法状态转换成功，失败方得到清楚的当前状态提示。
- [x] 取消后 SKU 库存页、销售单详情和业务审计展示一致的最新结果。
- [x] 取消失败时不产生部分预占释放或孤立审计记录。
- [x] 自动化测试覆盖权限、必填原因、数量恢复、非法状态、重复取消、事务回滚和并发状态竞争。

## Answer

- 在可串行化事务中锁定销售单与库存余额，原子完成状态变更、预占释放、`RELEASE` 库存活动和业务审计；并发状态竞争只允许一个转换成功。
- 列表与详情页按客户负责人/老板权限开放取消入口，弹窗展示逐 SKU 释放数量并校验非空原因；已取消详情永久只读并展示释放结果与审计轨迹。
- 取消权限策略和预览明细类型集中复用，避免列表、详情与写路径发生规则漂移。
- 自动化验证：销售单集成测试 20 项、全量 Vitest、TypeScript、ESLint、Next.js production build、Playwright E2E，以及 `product-ui` build / Sites tests 均通过。
- 正式 UI 与权威原型已同步，并在 `1440 × 1024` 与 `390 × 844` 下完成取消流程 QA；移动端无横向溢出。
