# 02 — 固定角色账号与首条业务审计

**What to build:** 让老板管理本地账号及固定角色，让每种角色进入符合职责的工作区，并以账号变更打通第一条可查询的业务审计轨迹，供后续业务动作复用。

**Blocked by:** 01 — 正式应用骨架与老板登录

**Status:** ready-for-agent

- [ ] 老板可以查看账号列表，并按姓名或邮箱、角色和启用状态筛选。
- [ ] 老板可以创建账号，设置姓名、唯一邮箱、初始密码，并从老板、销售、仓库、财务中分配至少一个固定角色。
- [ ] 一个账号可以同时拥有多个固定角色；登录后使用权限并集并展示相应导航，不提供角色模式切换器。
- [ ] 老板可以调整账号角色并停用账号；停用需要确认，停用账号不能新建会话。
- [ ] 非老板不能查看或调用账号管理能力，直接访问时得到不泄露资源信息的权限错误。
- [ ] 每个服务端入口统一检查会话、角色和必要的数据范围，客户端导航隐藏仅用于呈现。
- [ ] 账号创建、角色调整和停用与对应业务审计处于同一数据库事务，任一部分失败时全部回滚。
- [ ] 老板可以查看只追加的业务审计列表，至少包含操作者、动作、对象、时间和关联编号；审计记录不能编辑或删除。
- [ ] 角色首页和导航符合设计 PRD：老板进入经营总览，销售进入销售单，仓库进入待出库，财务进入应收。
- [ ] 自动化测试覆盖每种角色的允许与拒绝访问、多角色权限并集、停用账号登录失败以及账号动作的审计原子性。
