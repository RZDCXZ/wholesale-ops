# 01 — 正式应用骨架与老板登录

**What to build:** 建立可复现运行的正式应用，让老板使用预置账号真实登录、进入与设计原型一致的工作区并安全退出，同时为后续业务切片提供数据库、认证、测试和自动检查底座。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 项目使用已确定的 Node.js、pnpm、Next.js、PostgreSQL、Prisma 和 Better Auth 技术路线，并能通过一组文档化命令完成依赖安装、数据库启动、migration 和开发启动。
- [ ] 正式应用复用已通过设计 QA 的登录页、桌面框架、移动导航、颜色、密度和术语，不把静态原型中的模拟状态当作真实业务实现。
- [ ] 系统没有公开注册、找回密码、邮件验证或第三方登录入口。
- [ ] 预置老板账号可以登录并进入老板工作区；错误凭据只返回通用登录失败信息；未登录访问受保护页面会转到登录页。
- [ ] 老板可以退出，会话失效后不能继续访问受保护数据。
- [ ] 数据库会话持久化，服务端入口以真实会话作为身份来源，不能信任客户端提交的用户或角色信息。
- [ ] Pino 输出基础结构化运行日志，并默认排除密码、Cookie、授权头和会话值。
- [ ] Vitest 至少验证认证边界的稳定服务行为，Playwright 至少验证登录、失败登录、受保护页面和退出旅程。
- [ ] GitHub 自动检查能够运行依赖安装、代码检查、类型检查、测试和生产构建；初始主分支保持绿色。
- [ ] 提交 pnpm 锁文件、Node 主版本约束和环境变量示例，公开仓库中不包含真实密钥或凭据。
