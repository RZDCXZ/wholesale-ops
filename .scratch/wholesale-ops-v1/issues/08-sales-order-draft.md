# 08 — 销售单草稿

**What to build:** 让销售为自己负责的客户创建、编辑和删除销售单草稿，使用真实 SKU 与可用量形成一张可继续确认的交易记录。

**Blocked by:** 04 — 客户资料与负责人数据边界；07 — 期初库存导入与库存查询

**Status:** resolved

- [x] 销售可以为自己负责且启用的客户创建销售单草稿；老板可以为任意启用客户创建草稿。
- [x] 草稿支持多个 SKU 明细，每行搜索并选择启用 SKU、填写正整数数量和最多两位小数的人民币成交价。
- [x] 选择 SKU 时显示参考售价、库存单位和当前可用量；库存不足可以保存草稿但必须明确提示风险。
- [x] 系统计算每行小计和销售单成交金额，金额计算使用定点口径而非浮点误差结果。
- [x] 草稿保存客户名称、联系人、地址、客户负责人和账期等交易快照，后续客户资料变化不改写草稿快照。
- [x] 老板可以编辑或删除任意草稿；销售仅能编辑或删除自己创建且当前仍负责客户的草稿；其他销售、仓库和财务不能访问编辑能力。
- [x] 销售单列表按权限显示，并支持编号、客户、客户负责人、履约状态和日期筛选。
- [x] 离开有未保存修改的编辑页时给出提示，提交中阻止重复保存且校验失败保留输入。
- [x] 创建、编辑和删除草稿写入业务审计，并与销售单变更保持事务原子性。
- [x] 自动化测试覆盖客户数据范围、停用资料、整数和金额校验、快照稳定性、总额计算、草稿权限及审计。

## Answer

已完成真实 PostgreSQL 销售单草稿模型、应用服务、服务端操作和销售单列表/新建/编辑页面。草稿按分保存金额，保存完整客户与账期快照，从库存余额读取当前可用量并允许带缺货风险保存；列表、读取、编辑和删除均在服务端执行角色与数据范围校验，创建、编辑、删除和业务审计保持同事务原子性。桌面端与移动端均支持多明细编辑，SKU 可按编码或名称搜索，移动筛选使用全屏抽屉并展示已启用条件；表单还覆盖未保存离开提示、提交防重、错误输入保留、字段错误关联和对话框焦点恢复。

权限冲突按 `PROJECT_PLAN.md` 的高优先级业务边界裁决：客户负责人调整后，原负责人立即失去该客户及其销售业务访问权，因此销售编辑/删除同时要求“本人创建”和“当前仍负责”；老板始终可处理任意草稿。销售单确认与库存预占属于 ticket 09，本工单只提供可继续核对和确认的持久化草稿，不提前实现确认状态跳转。

Vitest/Testcontainers 覆盖客户范围、停用资料、整数与金额校验、快照稳定、总额、权限及审计回滚；Playwright 覆盖创建—校验—编辑—删除主旅程、缺货风险、未保存提示、会话切换拒绝、SKU 搜索、移动筛选和焦点恢复。正式页面已按 1440 × 1024 与 390 × 844 完成浏览器验收。
