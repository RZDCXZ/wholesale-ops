# 04 — 客户资料与负责人数据边界

**What to build:** 让老板和销售在明确的数据范围内维护客户，让财务只读查看客户，并让客户负责人真正成为服务端数据隔离规则。

**Blocked by:** 02 — 固定角色账号与首条业务审计

**Status:** resolved

- [x] 客户资料包含唯一客户编码、名称、联系人、电话、地址、一名客户负责人、默认账期和启用状态。
- [x] 老板可以创建和维护全部客户，并可以把客户负责人调整为任一启用销售账号。
- [x] 销售只能查看和维护由自己负责的客户，创建客户时负责人自动限定为自己。
- [x] 财务可以查看全部客户但不能修改；仓库没有独立客户列表访问权限。
- [x] 客户编码重复时创建失败，客户名称允许重复；创建后的客户编码在界面和服务端均不可修改。
- [x] 默认账期支持现结或非负整数天数，并以中国大陆业务语境清楚展示。
- [x] 列表支持按客户编码、名称、客户负责人和启用状态筛选，所有结果先应用服务端数据范围。
- [x] 老板和有权销售可以停用客户；被业务记录引用的客户不能删除。
- [x] 创建、编辑、负责人调整和停用动作写入业务审计，并与客户变更保持事务原子性。
- [x] 自动化测试直接调用服务端入口验证老板、销售、财务和仓库的数据边界，包括通过已知标识越权访问他人客户的失败场景。

## Answer

已完成客户资料、服务端负责人数据范围、老板转交、销售自有客户维护、财务只读和仓库拒绝访问。客户编码由数据库唯一约束与服务端不可变规则共同保护；账期使用现结或非负整数天数；列表组合筛选、分页和排序始终在数据范围内执行，并能筛选由已停用销售账号负责的历史客户。

创建、编辑、负责人调整、停用和未引用删除均与业务审计处于同一事务；负责人转交锁定客户行，编辑与停用使用带负责人谓词的原子更新，覆盖并发转交与多角色权限并集。正式页面提供列表、创建、详情和编辑独立 URL，在桌面使用宽表、手机使用卡片，并对尚未落地的销售/应收指标明确显示为后续接入而非虚假零值。

Vitest/Testcontainers 覆盖唯一编码、账期、数据范围、已知标识越权、负责人转交、并发审计链、删除引用保护和审计回滚；Playwright 覆盖老板完整维护旅程、转交后的范围切换、财务只读、仓库拒绝以及 Server Action 会话重检。ESLint、TypeScript、59 个 Vitest 测试、30 个 Playwright 测试和 Next.js 生产构建均通过。
