# 04 — 客户资料与负责人数据边界

**What to build:** 让老板和销售在明确的数据范围内维护客户，让财务只读查看客户，并让客户负责人真正成为服务端数据隔离规则。

**Blocked by:** 02 — 固定角色账号与首条业务审计

**Status:** ready-for-agent

- [ ] 客户资料包含唯一客户编码、名称、联系人、电话、地址、一名客户负责人、默认账期和启用状态。
- [ ] 老板可以创建和维护全部客户，并可以把客户负责人调整为任一启用销售账号。
- [ ] 销售只能查看和维护由自己负责的客户，创建客户时负责人自动限定为自己。
- [ ] 财务可以查看全部客户但不能修改；仓库没有独立客户列表访问权限。
- [ ] 客户编码重复时创建失败，客户名称允许重复；创建后的客户编码在界面和服务端均不可修改。
- [ ] 默认账期支持现结或非负整数天数，并以中国大陆业务语境清楚展示。
- [ ] 列表支持按客户编码、名称、客户负责人和启用状态筛选，所有结果先应用服务端数据范围。
- [ ] 老板和有权销售可以停用客户；被业务记录引用的客户不能删除。
- [ ] 创建、编辑、负责人调整和停用动作写入业务审计，并与客户变更保持事务原子性。
- [ ] 自动化测试直接调用服务端入口验证老板、销售、财务和仓库的数据边界，包括通过已知标识越权访问他人客户的失败场景。
