# 09 — 确认销售单并预占库存

**What to build:** 让销售或老板确认销售单草稿，在服务端原子校验并预占所有 SKU；库存不足或并发冲突时整单保持草稿且不产生部分预占。

**Blocked by:** 08 — 销售单草稿

**Status:** resolved

- [x] 有权用户可以从草稿详情发起确认，并在确认前看到客户、明细数、成交金额和各 SKU 的库存影响摘要。
- [x] 服务端确认时重新校验销售单状态、操作者数据范围、SKU 启用状态和最新可用量，不能依赖编辑页缓存值。
- [x] 任一 SKU 可用量小于所需数量时整单确认失败，错误指出 SKU、需要数量、当前可用量和缺少数量。
- [x] 确认成功后销售单变为已确认，业务内容冻结，现存量不变、预占量增加、可用量减少。
- [x] 所有明细预占、状态变化、库存流水和业务审计在同一数据库事务中完成。
- [x] 库存竞争使用可重试的串行化事务；两个请求同时争用最后库存时最多一个成功，不出现负可用量。
- [x] 并发失败显示“库存刚刚发生变化”类业务提示，销售单保持草稿并显示最新可用量。
- [x] 已确认、已出库或已取消销售单不能再次确认，也不能通过服务端入口静默编辑冻结内容。
- [x] 确认成功后页面展示更新后的履约状态、库存数字及相关库存流水和业务审计入口。
- [x] 自动化测试使用真实 PostgreSQL 覆盖成功确认、整单失败、事务回滚、重复确认、冻结内容和并发争用。

## Answer

已完成销售单确认与库存预占闭环。服务端确认入口在 PostgreSQL `Serializable` 事务中重新锁定并校验销售单、当前客户负责人范围、SKU 启用状态和最新库存余额；成功时一次性写入全部预占、销售单已确认状态、库存流水和业务审计，序列化冲突有限重试。库存不足和并发竞争均保持整单草稿，不产生部分预占，并返回 SKU、需要数量、最新可用量和缺少数量；确认后的客户快照、账期、SKU、数量与成交价继续由既有草稿写入口拒绝修改。

销售单详情与确认对话框已按正式原型实现：确认前展示客户、明细数、成交金额和逐 SKU 的现存量/预占量/可用量影响；库存不足时对话框、详情顶部和对应 SKU 行都显示服务端返回的最新差额，关闭对话框后提示仍会保留。成功后展示已确认与内容冻结状态、历史库存影响、履约记录，并按角色提供库存流水和业务审计入口。页面已在 1440 × 1024 与 390 × 844 下完成浏览器核对，无页面级横向溢出。

Vitest/Testcontainers 使用真实 PostgreSQL 覆盖成功确认、SKU 停用与权限复核、库存不足整单失败、业务审计失败全事务回滚、重复确认、冻结内容、详情读取和最后库存并发争用；Playwright 覆盖库存不足反馈、移动端确认、成功确认、冻结详情和追溯入口。全量 lint、类型检查、122 个 Vitest、40 个 Playwright 及生产构建均通过。
