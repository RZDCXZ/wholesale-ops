# 09 — 确认销售单并预占库存

**What to build:** 让销售或老板确认销售单草稿，在服务端原子校验并预占所有 SKU；库存不足或并发冲突时整单保持草稿且不产生部分预占。

**Blocked by:** 08 — 销售单草稿

**Status:** ready-for-agent

- [ ] 有权用户可以从草稿详情发起确认，并在确认前看到客户、成交金额和各 SKU 的库存影响摘要。
- [ ] 服务端确认时重新校验销售单状态、操作者数据范围、SKU 启用状态和最新可用量，不能依赖编辑页缓存值。
- [ ] 任一 SKU 可用量小于所需数量时整单确认失败，错误指出 SKU、需要数量、当前可用量和缺少数量。
- [ ] 确认成功后销售单变为已确认，业务内容冻结，现存量不变、预占量增加、可用量减少。
- [ ] 所有明细预占、状态变化、库存活动记录和业务审计在同一数据库事务中完成。
- [ ] 库存竞争使用可重试的串行化事务；两个请求同时争用最后库存时最多一个成功，不出现负可用量。
- [ ] 并发失败显示“库存刚刚发生变化”类业务提示，销售单保持草稿并显示最新可用量。
- [ ] 已确认、已出库或已取消销售单不能再次确认，也不能通过服务端入口静默编辑冻结内容。
- [ ] 确认成功后页面展示更新后的履约状态、库存数字及相关库存活动和业务审计入口。
- [ ] 自动化测试使用真实 PostgreSQL 覆盖成功确认、整单失败、事务回滚、重复确认、冻结内容和并发争用。
