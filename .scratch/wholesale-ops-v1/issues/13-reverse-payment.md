# 13 — 撤销收款

**What to build:** 让财务或老板用只追加的反向记录纠正错误收款，保留原收款事实并正确恢复未收金额、结算状态和逾期状态。

**Blocked by:** 12 — 部分收款与自动结清

**Status:** resolved

- [x] 财务或老板可以从有效收款记录发起撤销，并必须填写非空原因。
- [x] 撤销确认说明原收款金额、撤销后累计收款、未收金额和预期结算状态。
- [x] 撤销不会编辑或删除原收款，而是创建明确关联原记录的反向记录。
- [x] 撤销成功后累计有效收款和未收金额恢复，应收根据新余额变为待收款、部分收款或已结清。
- [x] 恢复未收金额后，逾期状态按当前日期和原到期日重新计算。
- [x] 一笔收款最多成功撤销一次；反向记录不能再次撤销，重复请求返回清楚结果且不重复改变金额。
- [x] 财务和老板以外角色不能撤销收款；销售看到的相关收款进度同步更新但不显示操作入口。
- [x] 反向记录、应收金额与状态更新、业务审计在同一数据库事务中完成。
- [x] 应收详情按时间清楚展示原收款及其撤销关系，不使用删除线以外的含糊表现代替文字状态。
- [x] 自动化测试覆盖已结清后撤销、部分收款撤销、重复撤销、权限、原因校验、逾期恢复和事务回滚。

## Answer

- 新增只追加且不可变的撤销收款反向记录，一笔原收款通过数据库唯一约束最多关联一条反向记录；原收款保持不变，反向记录不能再次撤销。
- 撤销服务使用串行化事务和应收行锁，原子写入反向记录、恢复累计有效收款与未收金额、重算结算状态并记录包含原因的业务审计；重复请求返回幂等结果。
- 应收详情为老板和财务提供必填原因的危险确认对话框，明确展示撤销前后金额与预计状态；时间线相邻展示“已撤销”原收款和文字清楚的反向记录，销售仅看到同步后的进度摘要。
- 已覆盖已结清后撤销、部分收款撤销、重复撤销、反向记录不可再次撤销、权限、原因校验、逾期恢复、数据库不可变约束和事务回滚；完成 1440px/390px 视觉与无横向溢出检查。
