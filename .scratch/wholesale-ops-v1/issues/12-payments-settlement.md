# 12 — 部分收款与自动结清

**What to build:** 让财务或老板查看经营应收并登记一次或多次有效收款，使累计收款、未收金额、逾期状态和结算状态自动保持一致。

**Blocked by:** 11 — 整单出库并生成应收

**Status:** resolved

- [x] 老板和财务可以查看全部应收列表与详情；销售只能查看自己负责客户的收款进度摘要；仓库不能访问应收数据。
- [x] 应收详情展示来源销售单、客户、原始金额、累计有效收款、未收金额、到期日、结算状态和逾期状态。
- [x] 财务或老板可以登记收款日期、金额、方式、参考号和备注，收款方式固定为现金、银行转账、微信、支付宝和其他。
- [x] 收款金额必须大于零且不能超过当前未收金额；系统不创建预收款、客户余额或跨应收分摊。
- [x] 一笔收款只能关联一笔应收，一笔应收允许登记多笔部分收款。
- [x] 首次部分收款后应收变为部分收款；累计有效收款等于原始金额时自动变为已结清，不提供独立结清按钮。
- [x] 超过到期日且未收金额大于零时派生为逾期应收；已结清应收不再显示逾期。
- [x] 已登记收款不能编辑或删除，重复提交不能产生重复收款。
- [x] 收款、应收金额与状态更新、业务审计在同一数据库事务中完成。
- [x] 自动化测试覆盖定点金额、多次部分收款、自动结清、零/负/超额金额、权限、逾期边界、重复提交和事务回滚。

## Answer

- 已实现真实应收列表、筛选、分页与详情；老板/财务可看完整款项，销售仅能查看自己客户的进度摘要，仓库无权限。
- 已新增不可变收款记录与五种收款方式；收款服务使用串行化事务、应收行锁和幂等键，原子更新应收汇总、状态与审计日志，防止重复入账和并发超收。
- 已实现多次部分收款、自动部分结清/结清、剩余金额校验，以及从到期日次日起算且结清后消失的逾期状态。
- 已补充 PostgreSQL 集成测试和 Playwright 端到端测试，覆盖权限边界、金额边界、幂等、并发、事务回滚、桌面与移动端收款流程。
- 已通过 `pnpm typecheck`、`pnpm lint`、`pnpm test`（144 项）、`pnpm test:e2e`（42 项）和 `pnpm build`，并完成桌面与移动端视觉检查。
