## Answer

- `pnpm setup` 现会启动 PostgreSQL、执行全部 migration、生成未纳入 Git 的本地认证密钥，并通过同一确定性重置入口装载 5 个账号、30 个 SKU、8 个客户和 20 张销售单。
- 演示数据按重置当天的中国标准时间生成，固定提供 3 张待出库销售单、2 笔部分收款、2 笔逾期应收、5 个库存预警 SKU、库存刚好足够/不足场景以及有效的今日指标和三十日收款趋势；凌晨重置不会生成晚于重置时刻的业务事件。
- `pnpm demo:reset -- --yes` 在销毁前显示目标和警告，并验证回环主机、固定数据库身份、`public` schema 及最新 migration；远程或错误目标在读取文件/连接前被拒绝。
- `pnpm db:backup` 与 `pnpm db:restore -- --input <file> --yes` 通过官方 PostgreSQL 18 Docker 镜像运行 `pg_dump` / `pg_restore`，生成并校验自定义格式备份，恢复前明确显示覆盖目标。
- 自动化覆盖三次重置确定性、相对日期、完整场景、历史演示引用兼容、空库初始化与登录、备份恢复和恢复后销售闭环、错误目标保护；已通过 Vitest 178 项、Playwright 44 项、TypeScript、ESLint 和 Next.js production build。
- Standards / Spec 双轴代码审查的 remaining findings 均为 0。
