# 16 — 确定性演示数据与备份恢复

**What to build:** 让项目作者一键得到完整、稳定且随当天日期保持合理的虚构业务场景，并能通过标准 PostgreSQL 工具备份和恢复本地数据。

**Blocked by:** 10 — 取消销售单并释放预占；13 — 撤销收款；14 — 经营总览

**Status:** ready-for-agent

- [ ] 演示重置生成 30 个 SKU、8 个客户、5 个演示账号和 20 张历史销售单。
- [ ] 演示账号包含老板、销售、仓库、财务四个单角色账号和一个多角色账号，账号说明不依赖真实邮箱或外部服务。
- [ ] 数据固定包含至少 2 张待出库销售单、2 笔部分收款、2 笔逾期应收、5 个库存预警 SKU，以及库存刚好足够和库存不足场景。
- [ ] 日期相对重置当天的中国标准时间生成，使今日指标、三十日趋势和逾期场景持续有效。
- [ ] 连续重置三次后账号、业务编号、数量、金额、状态分布和经营总览关键数字一致。
- [ ] 演示重置清楚警告会销毁本地演示数据，只作用于经过验证的本地数据库目标，不依赖宽泛路径或未校验环境变量。
- [ ] 初始化命令可以启动数据库、执行全部 migration、创建本地认证密钥并装载演示数据；密钥不提交到公开仓库。
- [ ] 备份命令通过 PostgreSQL 标准工具生成可识别的本地备份，恢复命令在覆盖前显示目标和破坏性警告。
- [ ] 从空数据库初始化以及从备份恢复后，用户可以登录并继续完成既定销售闭环。
- [ ] 自动化测试验证重置确定性、相对日期、完整场景、空库初始化、备份可恢复性和错误目标保护。
