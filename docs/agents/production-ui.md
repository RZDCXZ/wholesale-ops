# 正式前端页面

本文件适用于正式应用的页面开发。`product-ui/` 是视觉与交互基准；其原型代码、内存数据和页面切换方式不是生产架构。

## 开始前

对每个受影响页面完成以下准备：

1. 按 [`DESIGN_PRD.md`](../../DESIGN_PRD.md)“使用方式与需求来源”一节读取需求源和冲突优先级，再读取当前页面、角色、状态和响应式要求。
2. 在 [`product-ui/src/App.jsx`](../../product-ui/src/App.jsx) 中找到对应页面及交互状态，在 [`product-ui/src/styles.css`](../../product-ui/src/styles.css) 中找到相关视觉令牌和组件样式。
3. 查看对应的桌面端与移动端视觉基准；需要了解验收状态或交互覆盖范围时，再读 [`product-ui/design-qa.md`](../../product-ui/design-qa.md)。

准备完成的标准：每个受影响页面都已确定正式路由、适用角色、必须呈现的业务状态，以及对应的原型状态或明确不存在原型覆盖。

## 视觉与交互基准

正式实现应与原型保持以下方面一致：

- 页面布局与组件结构
- 信息密度、间距和层级
- 颜色、字体和状态表达
- 可见文案与交互反馈
- 桌面端和移动端响应式行为

主要视觉基准：

- 桌面端 `1440 × 1024`：[`implementation-desktop-final.png`](../../product-ui/design-qa/implementation-desktop-final.png)
- 移动端 `390 × 844`：[`implementation-mobile-final.png`](../../product-ui/design-qa/implementation-mobile-final.png)

原型只决定视觉和交互表现。术语、业务行为、权限、范围、页面要求和技术方案仍由 `DESIGN_PRD.md` 定义的对应需求源决定。

## 生产实现边界

按 [`PROJECT_PLAN.md`](../../PROJECT_PLAN.md) 中的技术方案实现正式页面，并遵守以下边界：

- 使用 Next.js App Router 和 `DESIGN_PRD.md` 的建议路由建立真实 URL；每个列表页、详情页、新建页和复杂编辑页位于对应路由目录。
- 按稳定职责提取应用框架、导航、表格、筛选器、表单控件、状态标签、对话框和抽屉等共享组件。
- 页面组件负责组合和呈现；服务端入口负责输入校验和鉴权；权限、状态跳转、库存、金额及其他业务规则由领域或应用服务负责。
- 使用 URL、服务端查询结果和必要的局部交互状态表达页面状态；业务事实应在刷新后保持一致。
- 可以复用原型的视觉令牌、交互模式、文案和虚构演示数据。数据库模型和稳定业务契约以正式需求与实现为准。

`product-ui/src/App.jsx` 集中页面、使用 `page` 状态切换视图和以内存状态模拟业务流转，均属于原型机制；正式实现需要按上述边界重新组织。

## 完成检查

完成页面变更前，逐个核对所有受影响页面：

1. 在 `1440 × 1024` 和 `390 × 844` 下比较对应原型或视觉基准，检查布局、组件结构、信息密度、间距、颜色、字体、可见内容、状态表达、交互反馈和响应式行为。
2. 验证当前改动涉及的角色导航、权限边界、加载与空状态、成功与失败反馈；移动端不得出现非预期横向溢出。
3. 确认每个独立页面拥有正式 URL，业务事实来自服务端，并且刷新后不会依赖全局内存状态恢复。
4. 逐项处理所有偏离：
   - 业务行为、权限、范围或术语变化，更新其权威需求源。
   - 页面或交互决策变化，更新 `DESIGN_PRD.md`。
   - 原型视觉基准变化，更新 `product-ui/` 及对应的 `design-qa` 记录和截图。
   - 仅因技术约束产生的有意偏离，记录原因和可见影响到当前 issue 或 spec；没有当前 issue 或 spec 时，在交付说明中逐项列出。

完成标准：上述检查覆盖每个受影响页面和视口，发现的每个偏离均已归类并处理。
